# AGENT PROTOCOL: Zero-Regression & Anti-Hallucination Directive

Цей документ є обов'язковою інструкцією для будь-яких AI-агентів та розробників, які виконують технічні завдання у репозиторії `olxparser`.

---

## 1. Залізний регресійний шлюз (Regression Gatekeeper)

Перед завершенням будь-якого таску та фіксацією змін у git виконавець **ЗОБОВ'ЯЗАНИЙ** запустити:

```bash
.venv/bin/python benchmark.py
.venv/bin/python -m unittest discover tests
```

### Критерії проходження (Definition of Done):
1. **Stress Failures = 0:** Жоден із 20 антигалюцинаційних стрес-тестів (`tests/data/stress_cases.json`) не повинен впасти.
2. **Overall Accuracy $\ge 95.0\%$:** Загальна точність за еталонним Golden Dataset (`tests/data/golden_raw_offers.json`) не має знижуватися.
3. **Unittest Pass:** Усі 90+ юніт-тестів мають проходити з кодом 0.

Якщо хоча б один тест падає — коміт або здача таску **СУВОРО ЗАБОРОНЕНІ**.

---

## 2. Архітектурні принципи парсингу адрес (Anti-Hallucination)

1. **Правило адресного контексту (Marker & Number Rule):**
   - Назва зі словника визнається вулицею лише за наявності адресного префікса (*вул.*, *просп.*, *бульв.*, *пров.* тощо) **АБО** номера будинку (*12*, *14-А*).
   - Одиночні прикметники або загальні слова (*зимовий*, *спортивна*, *новий*, *світла*, *зелена*, *шкільна*, *молодіжна* тощо) **КАТЕГОРИЧНО ЗАБОРОНЕНО** співставляти як вулицю без явного адресного маркера.
2. **Fail-Safe Default (Краще пусте поле, ніж брехня):**
   - Якщо в тексті оголошення немає чіткої адреси або є колізія орієнтирів (парки, метро, ТРЦ), поле `street` залишається пустим рядком `""`, а `district` заповнюється з офіційної геолокації оголошення OLX.
   - Замовнику надається валідна інформація, а не «галюцинація».
3. **Заборона штучних хаків:**
   - Заборонено писати `if "ID11..." in url:` або зав'язуватися на конкретні хеші оголошень. Усі виправлення мають бути узагальненими регулярними виразами або правилами нормалізації.

---

## 3. Принцип обробки атрибутів та заперечень

1. **Пріоритет заперечення (Negation Priority):**
   - Конструкції *«без інвертора»*, *«генератор відсутній»*, *«без тварин»*, *«немає»*, *«заборонено»* мають абсолютний пріоритет над позитивними згадками слів.
   - При виявленні заперечення статус встановлюється у `"no"`.
2. **Пріоритет заголовка над суперечливими чекбоксами:**
   - Якщо в заголовку або тексті автор прямо вказує *«можна з твариною»*, а в стандартних фільтрах OLX стоїть помилкова позначка `no`, пріоритет надається прямому тексту автора.

---

## 4. Додавання нових кейсів

Якщо замовник або тестувальник знаходить новий баг:
1. Спочатку додати цей кейс у `tests/data/stress_cases.json` або у відповідний юніт-тест.
2. Запустити `benchmark.py` і побачити, що кейс фіксує помилку.
3. Внести акуратні зміни до `normalizer.py`.
4. Запустити бенчмарк і переконатися, що новий кейс виправлено, а точність за іншими 156 оголошеннями не впала.
