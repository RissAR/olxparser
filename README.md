# OLX Kyiv Real Estate Parser & Web UI Dashboard

Професійний веб-сервіс (FastAPI + PWA Web UI + асинхронний фоновий парсер) для регулярного моніторингу та збору оголошень про оренду житлової та комерційної нерухомості з **OLX.ua** по місту **Київ** (всі 10 офіційних адміністративних районів).

Проєкт розроблено для повної автономної роботи на серверах VDS/VPS, обходу жорсткого ліміту пагінації OLX в 1000 оголошень, симетричного розподілу квот між категоріями та формування чистих, нормалізованих CSV-файлів у кодуванні `utf-8-sig` (UTF-8 з BOM) для прямої сумісності з Microsoft Excel.

---

## 🌟 Ключові можливості

- **Повний географічний обхід Києва:** Усі 10 районів міста (Голосіївський, Дарницький, Деснянський, Дніпровський, Оболонський, Печерський, Подільський, Святошинський, Солом'янський, Шевченківський).
- **Два цільових сегменти ринку:**
  - **Житлова нерухомість (23 колонки):** 1-, 2-, 3-, 4-, 5+-кімнатні квартири.
  - **Комерційна нерухомість (35 колонок):** Офіси, склади, торгові площі, кафе/ресторани, виробництва, МАФи, вільне призначення тощо.
- **Алгоритм бісекції цін (Price Bisection):** Автоматичний поділ діапазонів цін при виявленні понад 1000 оголошень у зрізі — дозволяє вивантажувати 100% масиву без втрат.
- **Рівномірний розподіл лімітів (Category Quotas):** При комбінованому зборі (`category="all"`) ліміт ділиться порівну між житловою та комерційною категоріями.
- **Щотижневі актуальні зрізи (Weekly Snapshot):** Фільтрація за останньою датою (`only_latest_date`), що виключає дублі та застарілі оголошення в щотижневих файлах.
- **Автоматичний архів з датами:** Створення як базових файлів, так і датованих копій виду `olx_residential_kyiv_YYYY-MM-DD.csv` та `olx_commercial_kyiv_YYYY-MM-DD.csv`.
- **Захист від блокувань:** Асинхронний клієнт `curl_cffi` з імітацією TLS-відбитка браузера Chrome, семафорним обмеженням конкурентності (3 потоки), експоненційним бекофом при HTTP 429/5xx та політними рандомізованими затримками (0.5–1.5 с).
- **Стійке збереження:** База даних SQLite у режимі WAL (`PRAGMA journal_mode=WAL;`) з повною дедуплікацією за URL та безпечною атомарною пакетною вставкою.
- **Інтерактивна веб-панель:** Сучасний Dark UI із живими метриками, таймером, прогрес-баром, швидким переглядом (Preview) та завантаженням згенерованих CSV.

## 🚀 Варіанти розгортання на VDS

---

### Варіант 1: Розгортання через Docker & Docker Compose (Рекомендовано)

Найбільш ізольований, безпечний та простий спосіб запуску на будь-якому VDS із встановленим Docker.

#### 1. Системні вимоги:
- Операційна система: Ubuntu 20.04+, Debian 11+, CentOS 8+, AlmaLinux тощо.
- Встановлений Docker та плагін `docker compose` (або `docker-compose` v2+):
  ```bash
  curl -fsSL https://get.docker.com | sh
  sudo usermod -aG docker $USER
  ```

#### 2. Клонування репозиторію:
```bash
git clone https://github.com/RissAR/olxparser.git
cd olxparser
```

#### 3. Підготовка директорій для персистентних даних:
```bash
mkdir -p data exports
```

#### 4. Запуск сервісу у фоновому режимі:
```bash
docker compose up -d --build
```

#### 5. Перевірка статусу та логів:
```bash
# Перевірка працездатності контейнера (health check)
docker compose ps

# Перегляд логів роботи в реальному часі
docker compose logs -f
```

#### 6. Робота з даними на хості:
- **База даних:** Зберігається на сервері за шляхом `./data/olx_storage.db` (монтується в `/app/data/olx_storage.db`).
- **CSV-файли експорту:** Зберігаються в папці `./exports/` на сервері (монтується в `/app/exports`). Файли одразу доступні як локально на сервері, так і для завантаження через браузер.

#### 7. Зупинка та оновлення:
```bash
# Зупинка контейнера
docker compose down

# Оновлення сервісу до останньої версії коду
git pull
docker compose up -d --build
```

### Варіант 2: Розгортання через Systemd (Нативна служба Linux)

Підходить для серверів під керуванням **Ubuntu 20.04 / 22.04 / 24.04** або **Debian 11 / 12**, коли потрібна робота безпосередньо в системі.

---

#### Спосіб 2.1: Автоматичне встановлення за 1 крок (через скрипт)

У репозиторії є перевірений скрипт [`setup_systemd.sh`](setup_systemd.sh), який автоматично виконує всі кроки конфігурації:

1. Клонуйте репозиторій та перейдіть у директорію:
   ```bash
   git clone https://github.com/RissAR/olxparser.git
   cd olxparser
   ```

2. Запустіть скрипт встановлення з правами `sudo`:
   ```bash
   sudo bash setup_systemd.sh
   ```

   **Скрипт автоматично:**
   - Перевірить наявність Python 3.
   - Створить віртуальне оточення `.venv`.
   - Оновить `pip` та встановить усі залежності з `requirements.txt`.
   - Створить робочі каталоги `data/` та `exports/` із правильними правами доступу.
   - Згенерує юніт-файл `/etc/systemd/system/olxparser.service` з автозапуском.
   - Перезавантажить `systemd`, увімкне автозапуск служби при завантаженні системи та запустить її.

---

#### Спосіб 2.2: Ручне покрокове встановлення

Якщо ви бажаєте самостійно контролювати кожну дію:

1. **Встановіть системні пакети:**
   ```bash
   sudo apt update
   sudo apt install -y python3 python3-venv python3-pip curl git
   ```

2. **Клонуйте репозиторій:**
   ```bash
   git clone https://github.com/RissAR/olxparser.git /opt/olxparser
   cd /opt/olxparser
   ```

3. **Створіть віртуальне оточення та встановіть бібліотеки:**
   ```bash
   python3 -m venv .venv
   .venv/bin/pip install --upgrade pip
   .venv/bin/pip install -r requirements.txt
   ```

4. **Створіть папки для бази даних та експортів:**
   ```bash
   mkdir -p data exports
   ```

5. **Створіть конфігураційний файл служби systemd:**
   Створіть файл `/etc/systemd/system/olxparser.service`:
   ```bash
   sudo nano /etc/systemd/system/olxparser.service
   ```
   Вставте наступний вміст (замініть `/opt/olxparser` та ім'я користувача `www-data` або вашого користувача за потреби):
   ```ini
   [Unit]
   Description=OLX Kyiv Real Estate Parser & Web UI Dashboard
   After=network.target

   [Service]
   Type=simple
   User=root
   Group=root
   WorkingDirectory=/opt/olxparser
   ExecStart=/opt/olxparser/.venv/bin/uvicorn app:app --host 0.0.0.0 --port 8000

   Environment="PYTHONUNBUFFERED=1"
   Environment="TZ=Europe/Kyiv"
   Environment="OLX_DB_PATH=/opt/olxparser/data/olx_storage.db"
   Environment="OLX_EXPORTS_DIR=/opt/olxparser/exports"
   Environment="PATH=/opt/olxparser/.venv/bin:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin"

   Restart=always
   RestartSec=5s
   KillMode=mixed
   TimeoutStopSec=30s

   StandardOutput=journal
   StandardError=journal
   SyslogIdentifier=olxparser

   [Install]
   WantedBy=multi-user.target
   ```

6. **Активуйте та запустіть службу:**
   ```bash
   sudo systemctl daemon-reload
   sudo systemctl enable olxparser.service
   sudo systemctl start olxparser.service
   ```

---

#### Керування службою Systemd:
```bash
# Перевірка поточного стану
sudo systemctl status olxparser

# Перегляд журналу логів у реальному часі
sudo journalctl -u olxparser -f

# Перезапуск служби (наприклад, після оновлення)
sudo systemctl restart olxparser

# Зупинка служби
sudo systemctl stop olxparser
```

## ⏰ Налаштування розкладу (Автоматичний щотижневий запуск)

Сервіс підтримує два взаємодоповнюючі механізми автоматичного запуску щотижневого парсингу:

### 1. Вбудований планувальник (APScheduler)
- Уже вбудований у веб-сервіс і активований за замовчуванням.
- Запускає повне сканування щопонеділка о **03:00** за київським часом (`Europe/Kyiv`).
- Може бути увімкнений або призупинений безпосередньо з веб-інтерфейсу або через API (`POST /api/scheduler/toggle`).

### 2. Зовнішній системний Crontab на сервері (Опціонально)
Якщо ви віддаєте перевагу надійному системному планувальнику Linux, відкрийте crontab:
```bash
crontab -e
```
Додайте рядок для щотижневого тригера щопонеділка о 03:00:
```cron
0 3 * * 1 /usr/bin/curl -s -X POST http://localhost:8000/api/cron/trigger > /dev/null 2>&1
```

## ⚙️ Змінні оточення (Configuration Reference)

| Змінна | За замовчуванням | Опис |

| `PORT` | `8000` | Мережевий TCP-порт для веб-інтерфейсу та REST API |

## 🌐 Веб-панель керування та REST API

Після запуску відкрийте у браузері: `http://<IP-вашого-сервера>:8000`

### Функціонал веб-інтерфейсу:
1. **Панель керування:**
   - Вибір категорії: *Усі категорії*, *Житлова*, *Комерційна*.
   - Обмеження кількості оголошень для збору (за замовчуванням повний збір).
   - Чекбокс автоматичного експорту після завершення збору.
   - Чекбокс **«Експортувати лише актуальний зріз (остання дата)»** для виключення застарілих лотів.
   - Кнопка **«Згенерувати CSV зараз з БД»** для миттєвого вивантаження наявних даних.
2. **Моніторинг сесії в реальному часі:**
   - Динамічний статус (Збір даних / Завершено / Очікування / Зупиняється).
   - Живий таймер тривалості сесії (`HH:MM:SS`).
   - Кількість знайдених та збережених оголошень, кількість помилок.
   - Відображення поточного зрізу (Район, кімнатність або тип комерції).
   - Інформація про наступний запланований автозапуск.
3. **Файловий менеджер експортів:**
   - Список усіх згенерованих файлів з метаданими (розмір, рядки, дата/час).
   - Кнопка **«Перегляд» (Preview)**: відкриває модальне вікно з першими 15 рядками таблиці без скачування.
   - Кнопка **«Завантажити» (Download)**: пряме скачування файлу з кодуванням `utf-8-sig`.

### Основні REST API ендпоінти:
| Метод | Ендпоінт | Опис |
| :--- | :--- | :--- |
| `GET` | `/` | Головна сторінка веб-інтерфейсу |
| `GET` | `/api/status` | Стан парсера, лічильники, статистика БД, стан розкладу |
| `POST` | `/api/scrape/start` | Запуск збору: `{"category": "all", "max_offers": null, "auto_export": true, "only_latest_date": true}` |
| `POST` | `/api/scrape/stop` | Безпечна зупинка активної сесії парсингу |
| `GET` | `/api/files` | Список готових CSV-файлів з метаданими |
| `GET` | `/api/download/{filename}` | Пряме скачування CSV-файлу (із захистом від Path Traversal) |
| `GET` | `/api/preview/{filename}` | Перегляд заголовків та перших рядків таблиці у форматі JSON |
| `POST` | `/api/export` | Ручний запуск експорту з БД: `{"category": "all", "only_latest_date": true}` |
| `GET/POST`| `/api/cron/trigger` | Зовнішній тригер для системного Linux cron |
| `POST` | `/api/scheduler/toggle` | Увімкнення / призупинення вбудованого розкладу APScheduler |

## 🧪 Верифікація, тести та контроль якості (QA Gate)

Проєкт оснащений повним комплектом інструментів автоматизованого контролю якості:

### 1. Golden Benchmark Suite (`benchmark.py`)
Перевіряє роботу алгоритму нормалізації та антигалюцинаційний захист на 156 реальних еталонних оголошеннях:
```bash
.venv/bin/python benchmark.py
```
*Результат: **100.00% точність (1020/1020 перевірок)**, 0 збоїв на стрес-тестах.*

### 2. Скрипт повної верифікації структури (`verify.py`)
Експортує дані та перевіряє їхню сувору відповідність шаблонам [`olx-manual-template.csv`](olx-manual-template.csv) (23 стовпці) та [`olx-commercial-template.csv`](olx-commercial-template.csv) (35 стовпців):
```bash
.venv/bin/python verify.py
```
*Перевіряє:*
- Наявність UTF-8 BOM (`\xef\xbb\xbf`).
- Точну кількість і порядок назв колонок.
- Відсутність порожніх обов'язкових полів та коректність типів даних.

### 3. Автоматизовані юніт- та інтеграційні тести
```bash
.venv/bin/python -m unittest discover tests
```
*Покриває:* розгортання, системні юніти, нормалізацію вулиць Києва, генератор зрізів, HTTP-клієнт, поділ квот, експорт та API.

└── tests/                      # Повний тестовий набір (94 тести)
