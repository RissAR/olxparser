# Kyiv Real Estate Multi-Source Parser & Web UI Dashboard
### OLX.ua • Rieltor.ua • LUN.ua

Високопродуктивний асинхронний сервіс (FastAPI + PWA Web UI + `curl_cffi` + SQLite WAL) для регулярного моніторингу та збору оголошень про оренду житлової та комерційної нерухомості одночасно з трьох головних майданчиків України: **OLX.ua**, **Rieltor.ua** та **LUN.ua** по місту **Київ** (усі 10 офіційних адміністративних районів).

Система розрахована на повністю автономну роботу на серверах VDS/VPS (включно з Hetzner), підтримує інкрементальний збір **виключно нових оголошень за тиждень**, паралельний запуск трьох парсерів, наскрізну дедуплікацію та формування чистих, валідованих CSV-файлів у кодуванні `utf-8-sig` (UTF-8 з BOM) для прямої роботи в Microsoft Excel / PowerBI.

---

## 🌟 Ключові можливості

1. **Три провідні джерела даних (Мульти-парсер):**
   - **OLX.ua:** Асинхронний мобільний REST API/SSR з бісекцією цін при перевищенні ліміту в 1000 лотів на зріз.
   - **Rieltor.ua:** Семантичний HTML-парсер із захистом від блокувань (Cloudflare/HTTP 429) та експоненційним бекофом.
   - **LUN.ua:** Парсер Next.js App Router RSC payload (`__next_f` JSON-стріми) з витягом точних гео-сутностей.

2. **Паралельне виконання (MultiSourceOrchestrator):**
   - Усі 3 майданчики скануються паралельно (`asyncio.gather`), скорочуючи час повного щотижневого циклу збору вдвічі (~75 000+ оголошень збираються приблизно за 1.5 години).
   - Повна ізоляція помилок: якщо один із сайтів тимчасово недоступний, інші завершують роботу штатно.

3. **Інкрементальний збір без дублів (Incremental Deduplication):**
   - Перед стартом сканування система завантажує індекс усіх раніше виявлених URL (`get_existing_urls`).
   - Оголошення, які вже є в базі за минулі тижні, миттєво пропускаються без зайвих мережевих запитів.
   - База зберігає первинну дату виявлення об'єкта (`seen_date`) та сесію першого відкриття (`first_session_id`).

4. **Два цільових сегменти ринку та ML-нормалізація:**
   - **Житлова нерухомість (23 колонки):** 1-, 2-, 3-, 4-, 5+-кімнатні квартири. Витяг поверховості, типу будинку (хрущовка, сталінка, спецпроект, новобудова), ремонту, наявності генератора в будинку, інвертора в квартирі, дозволу на тварин та дітей.
   - **Комерційна нерухомість (35 колонок):** Офіси, склади, торгові площі, кафе/ресторани, виробництва, медичні заклади, вільне призначення. Суворе умовне очищення полів (бізнес-центри — тільки для офісів, рампи та навантаження — тільки для складів).
   - **Stage 2 ЖК Fallback:** Автоматичне визначення житлових комплексів Києва та підстановка у поле «Вулиця» (`ЖК <Назва>`), якщо номер будинку відсутній.

5. **Монотонний прогрес-бар (Monotonic Slice Progress):**
   - Прогрес-бар відстежує реальну частку завершених зрізів і сторінок пагінації.
   - Показник прогресу монотонно зростає від 0% до 100% і ніколи не стрибає назад при відкритті нових сторінок чи переході між джерелами.

6. **Повна підтримка проксі (Proxy Support):**
   - Пряме налаштування HTTP/SOCKS5 проксі у веб-інтерфейсі або через змінну оточення `OLX_PROXY_URL`.
   - Критично важливо при розгортанні на іноземних VDS (Hetzner, OVH, DigitalOcean) для обходу гео-блокувань (HTTP 403) з боку LUN та Rieltor.

7. **Гнучкий та чистий набір CSV-файлів:**
   - **Окремі файли за платформами:**
     - `olx_residential_kyiv.csv`, `olx_commercial_kyiv.csv` (строго 23 і 35 колонок, тільки оголошення з OLX).
     - `rieltor_residential_kyiv.csv`, `rieltor_commercial_kyiv.csv` (тільки Rieltor).
     - `lun_residential_kyiv.csv`, `lun_commercial_kyiv.csv` (тільки LUN).
   - **Об'єднані категорії:**
     - `unified_residential_kyiv.csv` (житлова з 3 майданчиків + колонка `source`).
     - `unified_commercial_kyiv.csv` (комерційна з 3 майданчиків + колонка `source`).
   - **Єдиний майстер-файл:**
     - `unified_kyiv_real_estate.csv` (уся база Києва, 46 колонок, понад 75 000 записів).

## 🚀 Швидке встановлення та запуск на VDS

### Варіант 1: Нативна служба Systemd (Рекомендовано для Ubuntu/Debian)

1. **Клонуйте репозиторій:**
   ```bash
   git clone https://github.com/RissAR/olxparser.git /opt/olxparser
   cd /opt/olxparser
   ```

2. **Запустіть скрипт автоматичного встановлення:**
   ```bash
   sudo bash setup_systemd.sh
   ```
   Скрипт автоматично створить оточення `.venv`, встановить залежності, створить папки `data/` та `exports/`, налаштує і запустить системну службу `olxparser.service` з автозапуском після перезавантаження сервера.

3. **Керування службою:**
   ```bash
   sudo systemctl status olxparser    # Перевірка статусу
   sudo journalctl -u olxparser -f   # Перегляд логів наживо
   sudo systemctl restart olxparser  # Перезапуск
   sudo systemctl stop olxparser     # Зупинка
   ```

---

### Варіант 2: Запуск через Docker Compose

1. **Клонування та запуск:**
   ```bash
   git clone https://github.com/RissAR/olxparser.git
   cd olxparser
   mkdir -p data exports
   docker compose up -d --build
   ```

2. **Перевірка роботи:**
   ```bash
   docker compose ps
   docker compose logs -f
   ```

---

### Варіант 3: Ручний запуск для розробки та тестування

```bash
git clone https://github.com/RissAR/olxparser.git
cd olxparser
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# Запуск локального сервера на порту 8000
uvicorn app:app --host 0.0.0.0 --port 8000 --reload
```

## 🔄 Безшовне оновлення існуючої системи через Git

Якщо система вже була встановлена раніше, її можна оновити без перевстановлення та без втрати збережених даних:

1. Зупиніть сервіс:
   ```bash
   sudo systemctl stop olxparser  # або pkill -f uvicorn
   ```
2. Підтягніть зміни з GitHub:
   ```bash
   git pull origin main
   ```
3. Оновіть бібліотеки (за потреби):
   ```bash
   source .venv/bin/activate && pip install -r requirements.txt
   ```
4. Запустіть сервіс:
   ```bash
   sudo systemctl start olxparser
   ```
*База даних SQLite автоматично застосує міграцію структури таблиць під час першого запуску нової версії.*

## ⏰ Налаштування автоматичного розкладу

- **Вбудований планувальник (APScheduler):**  
  За замовчуванням активний і запускає повний паралельний збір щопонеділка о **03:00** за київським часом (`Europe/Kyiv`). Керувати розкладом (увімкнути/призупинити) можна прямо з веб-панелі.
- **Зовнішній системний Crontab (Опціонально):**  
  За потреби можна використовувати системний крон Linux:
  ```cron
  0 3 * * 1 /usr/bin/curl -s -X POST http://localhost:8000/api/cron/trigger > /dev/null 2>&1
  ```

## ⚙️ Змінні оточення (Configuration)

| Змінна | За замовчуванням | Опис |
| :--- | :--- | :--- |
| `PORT` | `8000` | Мережевий TCP-порт для веб-інтерфейсу та API |
| `TZ` | `Europe/Kyiv` | Часовий пояс для планувальника та часових міток |
| `OLX_DB_PATH` | `data/olx_storage.db` | Шлях до файлу бази даних SQLite |
| `OLX_EXPORTS_DIR` | `exports` | Каталог для збереження згенерованих CSV-файлів |
| `OLX_PROXY_URL` | *порожньо* | URL проксі за замовчуванням (наприклад, `http://user:pass@ip:port`) |
| `PYTHONUNBUFFERED` | `1` | Миттєве виведення логів без буферизації |

## 🌐 Веб-інтерфейс та REST API

Веб-панель доступна за адресою: `http://<IP-сервера>:8000`

### Функції UI:
- **Мульти-вибір джерел:** Можливість сканувати як усі 3 сайти одночасно, так і окремо будь-яку комбінацію (тільки OLX, тільки LUN тощо).
- **Вибір сегмента:** Всі категорії, тільки житлова або тільки комерційна.
- **Поле налаштування проксі:** Зручний ввід проксі прямо у браузері без редагування конфігураційних файлів на сервері.
- **Моніторинг підпроцесів:** Окремі живі картки стану для OLX, Rieltor та LUN з підрахунком зібраних оголошень.
- **Файловий менеджер:** Попередній перегляд (Preview) таблиць до завантаження та пряме скачування файлів.

### Основні ендпоінти API:
| Метод | Ендпоінт | Опис |
| :--- | :--- | :--- |
| `GET` | `/` | Головна сторінка дашборду |
| `GET` | `/api/status` | Поточний статус збору, лічильники джерел, статистика БД |
| `POST` | `/api/scrape/start` | Запуск сканування: `{"sources": ["olx", "rieltor", "lun"], "category": "all"}` |
| `POST` | `/api/scrape/stop` | Безпечна зупинка активних задач парсерів |
| `GET` | `/api/files` | Список згенерованих CSV-файлів з метаданими |
| `GET` | `/api/download/{filename}` | Скачування CSV-файлу |
| `GET` | `/api/preview/{filename}` | Швидкий перегляд перших рядків CSV у форматі JSON |
| `POST` | `/api/export` | Примусова регенерація CSV-файлів з БД |
| `POST` | `/api/scheduler/toggle` | Увімкнення / пауза щотижневого автозапуску |
