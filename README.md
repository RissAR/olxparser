# OLX Kyiv Real Estate Parser & Web UI Dashboard

Веб-сервіс (FastAPI + PWA Web UI + асинхронний фоновий парсер) на Python для регулярного збору та моніторингу оголошень про оренду житлової та комерційної нерухомості з OLX.ua по місту Київ (всі 10 районів) з обходом ліміту пагінації в 1000 оголошень та формуванням строго структурованих CSV-файлів у кодуванні `utf-8-sig` (UTF-8 with BOM).

---

## 🚀 Варіанти розгортання на VDS

### Варіант 1: Docker Compose (Рекомендовано)

Найпростіший та найбільш ізольований спосіб розгортання на будь-якому VDS із встановленим Docker / Podman:

1. **Клонування репозиторію:**
   ```bash
   git clone https://github.com/RissAR/olxparser.git
   cd olxparser
   ```

2. **Запуск контейнера у фоновому режимі:**
   ```bash
   docker compose up -d --build
   ```

3. **Перевірка статусу та логів:**
   ```bash
   docker compose ps
   docker compose logs -f
   ```

4. **Дані та збереження стану (Persistent Volumes):**
   - `./data`: Монтується до `/app/data` — зберігає SQLite базу даних (`olx_storage.db`) для дедуплікації оголошень та історії запусків.
   - `./exports`: Монтується до `/app/exports` — сюди зберігаються згенеровані CSV-файли (`olx_residential_kyiv.csv`, `olx_commercial_kyiv.csv`), які доступні як безпосередньо з хостової файлової системи, так і через Web UI кнопку завантаження.

5. **Зупинка та оновлення сервісу:**
   ```bash
   # Зупинка
   docker compose down

   # Оновлення коду та перезапуск
   git pull
   docker compose up -d --build
   ```

### Варіант 2: Розгортання безпосередньо на VDS через Systemd

Для серверів під керуванням Ubuntu 20.04/22.04/24.04 або Debian 11/12 доступний автоматизований скрипт налаштування:

1. **Автоматичне налаштування за один крок:**
   ```bash
   git clone https://github.com/RissAR/olxparser.git
   cd olxparser
   sudo bash setup_systemd.sh
   ```

   Скрипт автоматично:
   - Перевірить наявність Python 3.
   - Створить віртуальне оточення `.venv`.
   - Встановить усі необхідні залежності з `requirements.txt`.
   - Створить робочі каталоги `data/` та `exports/`.
   - Згенерує конфігураційний юніт `/etc/systemd/system/olxparser.service` з прив'язкою до поточної директорії та користувача.
   - Активує автозапуск при завантаженні системи (`systemctl enable`) та запустить службу.

2. **Керування службою:**
   ```bash
   # Перевірка статусу
   sudo systemctl status olxparser

   # Перегляд логів у реальному часі
   sudo journalctl -u olxparser -f

   # Перезапуск / Зупинка
   sudo systemctl restart olxparser
   sudo systemctl stop olxparser
   ```

## ⚙️ Змінні оточення (Configuration)

| Змінна | За замовчуванням | Опис |
| :--- | :--- | :--- |
| `PORT` | `8000` | Мережевий порт Web UI панелі та REST API |
| `TZ` | `Europe/Kyiv` | Часовий пояс для планувальника завдань APScheduler |
| `OLX_DB_PATH` | `data/olx_storage.db` | Шлях до файлу бази даних SQLite |
| `OLX_EXPORTS_DIR` | `exports` | Директорія для збереження згенерованих CSV-файлів |
| `PYTHONUNBUFFERED` | `1` | Виведення логів без буферизації |

## 🌐 Веб-панель керування та API

Після запуску сервіс доступний за адресою: `http://<IP-вашого-сервера>:8000`

- **Dashboard:** Інтерактивна панель керування парсером із живим опитуванням стану кожні 3 секунди, прогрес-баром, лічильниками знайдених оголошень та переліком готових файлів з кнопками скачування.
- **PWA Support:** Підтримка встановлення як нативного додатку на робочий стіл чи мобільний телефон (`manifest.json` + `sw.js`).
- **Планувальник:** Вбудований `APScheduler` за замовчуванням налаштований на щотижневий запуск щопонеділка о 03:00 (за київським часом). Можливе перемикання або примусовий запуск через API.

### Основні REST API ендпоінти:
- `GET /` — Головна сторінка веб-інтерфейсу.
- `GET /api/status` — Поточний стан парсера (idle/running/completed), статистика БД, час наступного запуску планувальника.
- `POST /api/scrape/start` — Ручний запуск парсингу (`{"category": "all" | "residential" | "commercial"}`).
- `POST /api/scrape/stop` — Безпечна зупинка активної сесії парсингу.
- `GET /api/files` — Список сформованих CSV-файлів з метаданими (розмір, кількість рядків, час створення).
- `GET /api/download/{filename}` — Пряме завантаження CSV-файлу.
- `POST /api/export` — Примусовий експорт поточного вмісту бази даних у CSV.
- `GET/POST /api/cron/trigger` — Ендпоінт для виклику зовнішнім системним cron (наприклад, `curl -X POST http://localhost:8000/api/cron/trigger`).
- `POST /api/scheduler/toggle` — Увімкнення/вимкнення вбудованого розкладу APScheduler.

## 🧪 Верифікація та тестовий запуск (Крок 7)

Модуль верифікації перевіряє точну відповідність згенерованих файлів референсним шаблонам [`olx-manual-template.csv`](olx-manual-template.csv) (23 колонки для житлової нерухомості) та [`olx-commercial-template.csv`](olx-commercial-template.csv) (35 колонок для комерційної нерухомості):

1. **Швидка перевірка поточної БД та сформованих CSV:**
   ```bash
   python verify.py
   ```

2. **Повний цикл із тестовим парсингом вибірки реальних оголошень:**
   ```bash
   python verify.py --sample-scrape --sample-size 5
   ```

3. **Запуск автоматизованого набору тестів:**
   ```bash
   python -m unittest discover tests
   ```

### Критерії верифікації:
- [x] **Структура заголовків:** точний порядок та назви всіх колонок (23 для житлової, 35 для комерційної).
- [x] **Кодування файлів:** обов'язковий префікс UTF-8 BOM (`\xef\xbb\xbf`) для прямої сумісності з Microsoft Excel (`utf-8-sig`).
- [x] **Числові поля:** цілі та десяткові числа без пробілів чи кому (десяткові строго з крапкою).
- [x] **Обмеження та енуми:** сувора валідація значень (`property_type`, `price_basis`, `seller`, `condition`, `furniture`, `building_class`).
- [x] **Локація:** прив'язка до офіційних 10 адміністративних районів Києва та словника вулиць `kyiv_streets.json`.
